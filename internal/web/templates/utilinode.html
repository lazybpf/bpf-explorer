Find the path behind an inode number. The kernel has no inode-to-path call, so both buttons search /proc and the filesystem as the agent sees them: with hostPID that is every process on the host. The look up button reads open file descriptors and file-backed memory mappings, the two places that record an inode next to a pathname: instant, but it only finds files some process holds right now. The walk filesystem button runs the equivalent of find -inum, which finds a file nothing has open, and every hard link to it, at the cost of stat-ing the tree.
